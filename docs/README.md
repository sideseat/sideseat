# SideSeat documentation site

The published docs at [sideseat.ai/docs](https://sideseat.ai/docs), built with
[Astro Starlight](https://starlight.astro.build).

From the repository root, which keeps the dependency tree in step with `package-lock.json`:

```bash
make dev-docs      # http://localhost:4321
make build-docs    # writes docs/dist/
make preview-docs  # serve what was built
```

Each of those installs through `npm ci` when the lockfile is newer than the install. Running `npm install`
here instead can *change* the lockfile to resolve an inconsistency, so the site you build locally and the
site CI builds would come from different versions with nothing saying so. The underlying scripts are
`npm run dev`, `npm run build` and `npm run preview`.

Mermaid diagrams (```` ```mermaid ````) are rendered to **static SVG at build time** by `rehype-mermaid`,
which drives a headless Chromium. So a diagram works with JavaScript disabled and ships no Mermaid runtime
to the reader, and one that fails to parse fails the build rather than rendering as an error box in the
page.

`make build-docs` downloads that browser on first use. On Linux it also needs system libraries, which
`make docs-system-deps` installs — separate because it needs sudo.

Content lives in `src/content/docs/docs/`. Pages are `.md` or `.mdx`; `.mdx` is needed for the
Starlight components (`<Tabs>`, `<Steps>`, `<Aside>`) and for the custom
`src/components/FrameworkDropdown.astro`.

## Adding a page

The sidebar in `astro.config.mjs` is hand-written, not autogenerated — a page without an entry
there is unreachable except by direct URL. Add the page and the sidebar entry together.

## Editing a framework integration

The same instructions are published in four places and must agree. Changing one means changing
all four:

| What | Where |
| ---- | ----- |
| Framework page | `src/content/docs/docs/integrations/frameworks/<framework>.mdx` |
| Homepage tabs | `src/content/docs/docs/index.mdx` (SDK tab and Direct OTLP tab) |
| Telemetry config UI | `../web/src/pages/configuration/telemetry-frameworks.ts` |
| MCP `setup_guide` | `../server/src/api/mcp/tools.rs` |

The web snippets are checked by `web/src/pages/configuration/__tests__/telemetry-snippets.test.ts`,
which parses every Python snippet with a real interpreter, and the MCP snippets by tests in
`tools.rs` that require every name a snippet calls to be imported or assigned in that snippet.
Nothing checks the `.mdx` pages automatically, so verify those by running what they tell users
to run.
