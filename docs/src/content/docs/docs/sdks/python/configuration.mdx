`sideseat.init` takes keyword arguments. Each falls back to its environment variable, then to a default.

| Argument | Environment | Default |
| --- | --- | --- |
| `endpoint` | `SIDESEAT_ENDPOINT`, then `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://127.0.0.1:5388` |
| `project` | `SIDESEAT_PROJECT_ID` | `default` |
| `api_key` | `SIDESEAT_API_KEY` | none |
| `service_name` | `OTEL_SERVICE_NAME` | the primary integration's package name |
| `service_version` | `OTEL_SERVICE_VERSION` | that package's version |
| `integrations` | `SIDESEAT_INTEGRATIONS` (comma-separated) | detected |
| `capture_content` | `SIDESEAT_CAPTURE_CONTENT` | `True` |
| `disabled` | `SIDESEAT_DISABLED` | `False` |
| `debug` | `SIDESEAT_DEBUG` | `False` |
| `export` | | `True` |
| `metrics` | | `True` |
| `logs` | | `True` |
| `capture_python_logs` | | `False` |
| `resource_attributes` | `OTEL_RESOURCE_ATTRIBUTES` (merged underneath) | none |
| `span_processors` | | none |

Boolean variables accept `1`/`0`, `true`/`false`, and `yes`/`no`. Any other value raises
`ConfigurationError` instead of silently using the default. An empty or blank argument or variable
counts as unset and falls back to the next source; `integrations=[]`, an empty list, means none.

## Endpoint

An endpoint without a path is a SideSeat server, and telemetry goes to its project:
`http://host:5388` sends traces to `http://host:5388/otel/<project>/v1/traces`. An endpoint with a path
is already an OTLP base and is used as given. The project is URL-encoded as one path segment, which is how to send through a collector:
`https://collector.example.com/otel/team-a` sends traces to `.../otel/team-a/v1/traces`.

## Authentication

With authentication enabled on the server - the default - pass an API key for the organization that
owns the project. It is sent as `Authorization: Bearer <key>`. Headers from
`OTEL_EXPORTER_OTLP_HEADERS` are sent too; the API key replaces an `Authorization` header of any
spelling there, so exactly one credential is sent.

## Content

Prompts, responses, tool arguments, and tool results are recorded by default, because reading the
conversation is the point of SideSeat. `capture_content=False` turns content off in every integration.
SideSeat sets the standard `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` to match. Content off,
or a `capture_content=True` argument, replaces a value already in that variable; otherwise SideSeat sets
it to `true` only when it is unset, so `SIDESEAT_CAPTURE_CONTENT=true` does not override a `false` there. Images and documents are exported as base64 and moved to file storage by the
server.

## Logs and metrics

Log records are exported because several instrumentations emit GenAI content as log events.
`capture_python_logs=True` additionally exports records from the `logging` root logger. Metrics are
exported every minute; turn them off with `metrics=False`. When Logfire owns the providers, SideSeat's
log processor and metric reader go into Logfire's, so its metrics reach SideSeat too.

## An existing OpenTelemetry setup

When the application has already installed an OpenTelemetry tracer or logger provider, SideSeat adds
its processors and exporter to it instead of replacing it. At shutdown it stops what it added and
leaves the provider itself to the application. Signals then carry the application's resource. An
application meter provider gets SideSeat's metric reader the same way, and shutdown removes it. That
needs `opentelemetry-sdk` 1.44 or later; with an older SDK, `init` warns with the metrics URL, and the
application adds the reader where it builds its provider:

```python
from opentelemetry.exporter.otlp.proto.http.metric_exporter import OTLPMetricExporter
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader

reader = PeriodicExportingMetricReader(
    OTLPMetricExporter(endpoint="http://127.0.0.1:5388/otel/default/v1/metrics")
)
provider = MeterProvider(metric_readers=[reader, *your_readers])
```

Frameworks that build their own provider - Logfire and Browser Use's Laminar - own it, and SideSeat
attaches to theirs. Their exporters follow SideSeat's settings: with `export=False` Laminar sends
nothing, and its log records go to the logs endpoint through SideSeat's log processor.

## Calling init twice

`init` configures the process. Calling it again with the same arguments returns the same client;
different arguments raise `ConfigurationError`, because a second configuration would silently leave the
process exporting with whichever came first. OpenTelemetry's global providers can be set once per
process, so `init` after `sideseat.shutdown()` raises too; tests that need a fresh pipeline use
`sideseat.testing.capture`.

## Integrations that are missing

An integration you name must be usable: if its framework or the packages of its `sideseat[...]` extra
are not installed, `init` raises `IntegrationError` with the install command. A detected integration
that cannot start is skipped with a warning, and is then left out of `service.name`,
`sideseat.framework`, and `sideseat.integrations`.

## Disabling

`disabled=True` or `SIDESEAT_DISABLED=true` configures nothing. Every SideSeat call still works and
records nothing, so the same code runs in tests and in production.
