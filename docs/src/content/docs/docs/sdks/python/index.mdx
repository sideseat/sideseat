`sideseat` is an OpenTelemetry distribution for AI applications. One call configures tracing, logs,
and metrics for a SideSeat project, switches on your framework's telemetry, and attributes every span
to the right session and user.

## Install

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install sideseat
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add sideseat
    ```
  </TabItem>
</Tabs>

Python 3.11 or newer. Some integrations need an extra, for example `pip install "sideseat[langgraph]"`;
the [integration table](#integrations) lists them.

Start a local server with `npx sideseat` and open [http://localhost:5388](http://localhost:5388).

## Quick start

```python
import sideseat
from strands import Agent

sideseat.init(integrations=["strands"])

agent = Agent(model="global.anthropic.claude-sonnet-5-5")

with sideseat.session("conversation-42", user_id="user-7"):
    agent("Plan a weekend in Lisbon.")
    agent("What should I eat there?")
```

That is the whole setup. `init` points OpenTelemetry at `http://127.0.0.1:5388` and the `default`
project; the [configuration page](/docs/sdks/python/configuration/) covers servers elsewhere, API keys,
and every other option.

## Sessions and users

`sideseat.session(session_id, user_id=...)` is a scope, not a span. Every span started inside it - the
ones your framework creates included - gets `session.id` and `user.id`, so SideSeat groups the traces
of one conversation into one session.

The identifiers follow the OpenTelemetry context through `async` code and threads that propagate it.
They are never sent as W3C baggage: HTTP instrumentation forwards baggage to every service you call,
including model providers.

## Traces and spans

```python
with sideseat.trace("plan-trip", session_id="s-1", user_id="u-1"):
    with sideseat.span("retrieve-context") as span:
        span.set_attribute("app.documents", 4)
        documents = load_documents()
    agent(f"Plan a trip using: {documents}")


@sideseat.observe()
async def load_documents() -> list[str]:
    ...
```

- `trace()` always starts a new root span, even inside another span.
- `span()` starts a child of the active span.
- `observe()` wraps each call of a function, sync or async, in a span named after it.

An exception inside any of them is recorded on the span, which is marked as failed, and re-raised.

## Integrations

Pass the frameworks and providers you use; the first one is the primary integration and names the
service. Without `integrations`, the installed framework is detected. Provider client libraries are
never detected - frameworks install them transitively - so name them explicitly.

Each framework's page under [Integrations](/docs/integrations/) shows its setup with and without the SDK.

## Flushing and shutdown

Telemetry is exported in batches. `sideseat.shutdown()` runs at exit, including on `SIGTERM` when no
other handler is installed, and flushes everything; call `sideseat.flush()` yourself in a short-lived
process, such as a serverless handler, before it is frozen. Both take a timeout in milliseconds that
bounds the whole call, return whether everything was exported within it, and never raise because of
telemetry. A second `shutdown()` reports the first one's result.

## Testing your application

`sideseat.testing.capture()` initializes SideSeat without network export and records spans in memory:

```python
from sideseat.testing import capture


def test_the_agent_reports_its_session():
    with capture(integrations=["strands"]) as spans:
        with sideseat.session("s-1"):
            run_agent()
    assert all(span.attributes["session.id"] == "s-1" for span in spans.finished())
```

## The runtime channel

Agents registered over the [runtime channel](/docs/sdks/python/runtime/) appear in the SideSeat UI,
which can inspect and run them.
