SideSeat instruments the current `google-genai` client in its Google Cloud mode. It captures
model information, token usage, complete message history, streaming responses, tool calls, and
costs from Gemini models served through Vertex AI.

<Aside type="caution">
Google Gen AI SDK 2.28 uses `enterprise=True` for the API previously selected with the legacy
Vertex flag. The older Vertex AI Python client is not the current integration path. SideSeat still
reads its historical telemetry when it was already stored, but new applications should use the
setup below.
</Aside>

## Prerequisites

- SideSeat running locally (`sideseat`)
- A Google Cloud project with the Vertex AI API enabled
- [Application Default Credentials](https://cloud.google.com/docs/authentication/provide-credentials-adc)
- The SideSeat Vertex extra:

```bash
pip install "sideseat[vertex-ai]"
```

The extra installs the Google Gen AI client and Logfire's Google Gen AI OpenTelemetry
instrumentor. Installing plain `sideseat` does not install either optional dependency.

## Quick start

```python
from google import genai
from sideseat import Frameworks, SideSeat

SideSeat(framework=Frameworks.VertexAI)

client = genai.Client(
    enterprise=True,
    project="your-project",
    location="us-central1",
)
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="What is the speed of light?",
)
print(response.text)
```

The same client can be configured through environment variables:

```bash
export GOOGLE_GENAI_USE_ENTERPRISE=true
export GOOGLE_CLOUD_PROJECT=your-project
export GOOGLE_CLOUD_LOCATION=us-central1
```

```python
from google import genai

client = genai.Client()
```

## Streaming and retained history

The chat API re-sends retained history on later requests. SideSeat reconstructs the conversation
once, in causal order, without duplicating earlier turns:

```python
from google.genai import types

chat = client.chats.create(
    model="gemini-2.5-flash",
    config=types.GenerateContentConfig(
        system_instruction="Answer scientific questions in one sentence.",
    ),
)

first = chat.send_message("What is the speed of light?")
print(first.text)

for chunk in chat.send_message_stream("What is the boiling point of water?"):
    print(chunk.text or "", end="", flush=True)
```

The resulting role sequence is:

```text
system → user → assistant → user → assistant
```

## Tool use

Python functions can be passed directly to the Google SDK. Its automatic function-calling loop
executes the function and asks the model for the final answer:

```python
from google.genai import types


def get_weather(location: str) -> str:
    """Get the current weather for a location."""
    return f"Sunny and 22°C in {location}."


chat = client.chats.create(
    model="gemini-2.5-flash",
    config=types.GenerateContentConfig(tools=[get_weather]),
)
response = chat.send_message("What's the weather in London?")
print(response.text)
```

SideSeat keeps the tool definition, call ID, arguments, result, and final answer in this order:

```text
user → assistant tool_use → tool tool_result → assistant
```

## Traces and sessions

Use explicit SideSeat traces when several model calls belong to one application operation. Reuse
the same session ID to group independent traces into one user session:

```python
from google import genai
from sideseat import Frameworks, SideSeat

sideseat = SideSeat(framework=Frameworks.VertexAI)
vertex = genai.Client(
    enterprise=True,
    project="your-project",
    location="us-central1",
)

session_id = "session-123"
user_id = "user-456"

with sideseat.trace("scientific-history", session_id=session_id, user_id=user_id):
    vertex.models.generate_content(
        model="gemini-2.5-flash",
        contents="What is the speed of light?",
    )

with sideseat.trace("weather-question", session_id=session_id, user_id=user_id):
    vertex.models.generate_content(
        model="gemini-2.5-flash",
        contents="What is the weather in London?",
    )
```

## Without the SideSeat SDK

Install and configure the same instrumentor directly:

```bash
pip install google-genai "logfire[google-genai]>=4.29.0" opentelemetry-exporter-otlp
```

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_SERVICE_NAME=my-vertex-app
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
```

```python
import logfire

logfire.configure(send_to_logfire=False, console=False)
logfire.instrument_google_genai()
```

Create `genai.Client(enterprise=True, ...)` after instrumentation is installed.

## Detection

The Developer API and Vertex AI use the same `google-genai` package and instrumentation scope, so
package presence cannot identify which provider an application uses. Pass
`Frameworks.VertexAI` explicitly when using the SideSeat SDK.

Native telemetry is identified by the exact
`opentelemetry.instrumentation.google_genai` scope together with
`gen_ai.provider.name=vertex_ai`. The provider attribute is required because the scope is shared
with the Gemini Developer API.

## Authentication

For local development:

```bash
gcloud auth application-default login
```

In production, use the workload's attached service account or another supported Application
Default Credentials source. A downloaded service-account key can be selected with
`GOOGLE_APPLICATION_CREDENTIALS`, but workload identity is preferable when the platform supports
it.

## Verified contract

The checked-in native and SideSeat fixtures use Google Gen AI 2.28.0, Logfire 5.1.1, Google Gen
AI OpenTelemetry instrumentor 1.2b0, OpenTelemetry Python 1.44.0, and CPython 3.13.7. They verify:

- non-streaming and streaming responses;
- retained multi-turn history without duplicates;
- a complete automatic tool-call, result, and final-answer roundtrip;
- two traces grouped into one session;
- identical span, trace, session, and project-feed answers with and without the SDK;
- six spans, two traces, one session, and zero unresolved review warnings.
