SideSeat works with any framework that emits OpenTelemetry traces. This page covers frameworks without dedicated integration pages.

## LangChain

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install langchain langchain-openai "sideseat[langchain]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add langchain langchain-openai "sideseat[langchain]"
    ```
  </TabItem>
</Tabs>

```python
from sideseat import SideSeat, Frameworks
from langchain_openai import ChatOpenAI

SideSeat(framework=Frameworks.LangChain)

llm = ChatOpenAI(model="gpt-5-mini")
response = llm.invoke("Hello!")
print(response.content)
```

<Aside type="tip">
For stateful agent workflows, use [LangGraph](/docs/integrations/frameworks/langgraph/) instead.
</Aside>

The compatibility corpus exercises LangChain 1.4.3, LangChain Core 1.6.6,
LangChain OpenAI 1.6.7, and OpenInference's LangChain instrumentor 0.1.76 on
OpenTelemetry Python 1.45.0. Native OpenTelemetry and SideSeat SDK captures must
produce identical span projections, two trace conversations, their shared session,
and the project feed. The scenario includes multi-turn history, streaming, and a
complete tool-call roundtrip.

<Tabs>

  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add pydantic-ai "sideseat[pydantic-ai]"
    ```
  </TabItem>

```python
from sideseat import SideSeat, Frameworks
from pydantic_ai import Agent

SideSeat(framework=Frameworks.PydanticAI)

agent = Agent('openai:gpt-5-mini')
result = agent.run_sync('What is the capital of France?')
print(result.output)
```

The compatibility corpus exercises Pydantic AI 2.50.0 with and without the SideSeat SDK,
including multi-turn history and tool use. `pydantic_ai.all_messages` is expanded into its
individual turns at read time, so the history snapshot does not appear as an extra context
message beside the model-call spans.

## LlamaIndex

LlamaIndex uses its own instrumentation dispatcher rather than emitting OpenTelemetry directly.
SideSeat's `llama-index` extra installs the OpenInference bridge and binds it to the same tracer
provider and exporter as the rest of the application:

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install llama-index "sideseat[llama-index]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add llama-index "sideseat[llama-index]"
    ```
  </TabItem>
</Tabs>

```python
from sideseat import SideSeat, Frameworks
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

SideSeat(framework=Frameworks.LlamaIndex)

documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()

response = query_engine.query("What is this about?")
print(response)
```

The compatibility corpus exercises LlamaIndex Core 0.14.25, LlamaIndex OpenAI 0.8.2,
OpenInference's LlamaIndex instrumentor 4.5.3, and OpenTelemetry Python 1.45.0 on Python 3.13.
The OpenAI adapter currently requires `openai <3`, so the capture uses OpenAI 2.54.0, the newest
compatible release resolved by the lockfile.

Native OpenTelemetry and SideSeat SDK captures must produce identical span projections, two
trace conversations, their shared session, and the project feed. The scenario covers retained
history, a streamed second answer, and one automatic weather-tool roundtrip. LlamaIndex workflow
and request-preparation spans remain available as raw telemetry, but their serialized internal
state is not presented as conversation messages.

## AutoGen

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install autogen-agentchat "autogen-ext[openai]" "sideseat[autogen]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add autogen-agentchat "autogen-ext[openai]" "sideseat[autogen]"
    ```
  </TabItem>
</Tabs>

```python
import asyncio

from sideseat import SideSeat, Frameworks
from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient

SideSeat(framework=Frameworks.AutoGen)


async def main():
    model_client = OpenAIChatCompletionClient(model="gpt-5-mini", api_key="sk-xxx")
    assistant = AssistantAgent("assistant", model_client=model_client)
    result = await assistant.run(task="Hello!")
    print(result.messages[-1].content)


asyncio.run(main())
```

## Agno

```bash
pip install agno openai "sideseat[agno]"
```

```python
from sideseat import SideSeat, Frameworks
from agno.agent import Agent
from agno.models.openai import OpenAIChat

SideSeat(framework=Frameworks.Agno)

agent = Agent(model=OpenAIChat(id="gpt-5-mini"), tools=[])
agent.print_response("Hello!")
```

Agno is instrumented through OpenInference. Its spans carry `agno.*` attributes alongside
`openinference.*`, and SideSeat's detection prefers the specific `agno.` prefix so runs are
labelled Agno rather than the generic OpenInference.

The tracked compatibility boundary is Agno 3.0.11 with OpenAI 3.22.1 and the OpenInference
Agno instrumentor 1.0.12 on Python 3.13. It is exercised both natively and through SideSeat
with persisted history, streaming, automatic tool execution, two traces, and one shared session.

## Smolagents

```bash
pip install smolagents "sideseat[smolagents]"
```

```python
from sideseat import SideSeat, Frameworks
from smolagents import OpenAIModel, ToolCallingAgent

SideSeat(framework=Frameworks.Smolagents)

model = OpenAIModel(model_id="gpt-5-mini")
agent = ToolCallingAgent(tools=[], model=model)
agent.run("What is 2+2?")
```

Smolagents uses OpenInference telemetry. Only the agent run span carries `smolagents.*`;
the step, model, and tool spans are identified by the exact
`openinference.instrumentation.smolagents` scope.

The tracked compatibility boundary is Smolagents 1.26.0 with OpenAI 3.22.1, the OpenInference
Smolagents instrumentor 0.1.41, and OpenTelemetry Python 1.45.0 on Python 3.13. Native
OpenTelemetry and SideSeat captures must produce identical span projections, two trace
conversations, their shared session, and the project feed. The scenario retains history across
runs, streams the second answer, executes a custom weather tool, and verifies every
`final_answer` call/result pair without exposing Smolagents' internal `Calling tools` and
`Observation` renderings as user messages.

## AG2

```bash
pip install "ag2[openai]>=1.1.1,<2" "sideseat[ag2]"
```

```python
import asyncio

from ag2 import Agent
from ag2.config import OpenAIConfig
from sideseat import SideSeat, Frameworks

SideSeat(framework=Frameworks.AG2)

assistant = Agent(
    "assistant",
    "Answer briefly.",
    config=OpenAIConfig(model="gpt-5-mini"),
)

async def main():
    reply = await assistant.ask("Hello!")
    print(await reply.content())

asyncio.run(main())
```

Initialize SideSeat before constructing the agent. SideSeat injects AG2 1.x's native
`TelemetryMiddleware` with content capture and the SideSeat tracer provider; an explicit
`TelemetryMiddleware` is preserved rather than duplicated.

The tracked compatibility boundary is AG2 1.1.1 with OpenAI 3.22.1 and OpenTelemetry Python
1.45.0. Native OpenTelemetry and SideSeat captures have identical span projections, two trace
conversations, their shared session, and the project feed. The scenario covers retained history,
streaming, automatic tool execution, and the complete tool call/result/final-answer sequence.

## AgentScope

```bash
pip install agentscope sideseat
```

```python
from sideseat import SideSeat, Frameworks

SideSeat(framework=Frameworks.AgentScope)

# AgentScope emits OpenTelemetry itself and only needs the provider SideSeat installs.
```

No extra is needed: AgentScope exports spans through the global tracer provider. Its spans
carry `agentscope.*` attributes and `gen_ai.conversation.id`, which SideSeat reads as the
session id.

## Langflow

```bash
pip install langflow sideseat
```

Langflow emits OpenTelemetry itself. Either run it in a process where SideSeat has
installed the provider, or point Langflow's own OTLP exporter at SideSeat:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
```

Flow spans carry `langflow.flow_id`, `langflow.flow_name` and `langflow.session_id`.

## Haystack

```bash
pip install haystack-ai "sideseat[haystack]"
```

```python
from sideseat import SideSeat, Frameworks
from haystack import Pipeline
from haystack.components.generators.chat import OpenAIChatGenerator
from haystack.dataclasses import ChatMessage

SideSeat(framework=Frameworks.Haystack)

pipeline = Pipeline()
pipeline.add_component("llm", OpenAIChatGenerator(model="gpt-5-mini"))
result = pipeline.run({"llm": {"messages": [ChatMessage.from_user("Hello")]}})
print(result["llm"]["replies"][0].text)
```

Component spans carry `haystack.component.name` and `haystack.component.type`, which
SideSeat uses to label the run Haystack rather than generic OpenInference.

## browser-use

```bash
pip install browser-use sideseat
```

```python
import asyncio

from sideseat import SideSeat, Frameworks
from browser_use import Agent, ChatOpenAI

SideSeat(framework=Frameworks.BrowserUse)


async def main():
    agent = Agent(task="Find the docs", llm=ChatOpenAI(model="gpt-5-mini"))
    print(await agent.run())


asyncio.run(main())
```

No extra is needed: browser-use exports OpenTelemetry through the global provider. Every
span it emits sets `gen_ai.provider.name = "browser_use"`, which is how SideSeat detects it.

## Recognised without a setup guide

The server classifies these, but nothing here tells you how to wire them up — each already emits
OpenTelemetry on its own, so the generic setup below is the whole instruction and the spans are
attributed once they arrive:

| Framework | Recognised by |
| --- | --- |
| Semantic Kernel | current Python instrumentation scopes and `semantic_kernel.*` attributes |
| Azure AI Foundry | Azure AI attributes, after the more specific Azure OpenAI rule |
| Logfire | Pydantic Logfire's own attributes |
| MLflow | MLflow tracing attributes |
| TraceLoop | OpenLLMetry / TraceLoop attributes |
| LiveKit | LiveKit Agents attributes |

Semantic Kernel is exercised by a paired native/SideSeat capture. Logfire's provider dialects are
also exercised by paired native/SideSeat captures for OpenAI 3.19.2 and Anthropic 1.8.0
(Logfire 6.0.0b7); the remaining rows are classifier-only. The support matrix in
`server/tests/fixtures/messages/README.md` is the exact boundary of what is verified.

## Generic OpenTelemetry

For frameworks not listed above, send traces directly via the OpenTelemetry SDK:

<Steps>
1. **Start SideSeat**

   ```bash
   npx sideseat
   ```

2. **Set the endpoint**

   ```bash
   export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
   ```

3. **Install and configure**

   <Tabs>
     <TabItem label="pip">
       ```bash
       pip install opentelemetry-sdk opentelemetry-exporter-otlp
       ```
     </TabItem>
     <TabItem label="uv">
       ```bash
       uv add opentelemetry-sdk opentelemetry-exporter-otlp
       ```
     </TabItem>
   </Tabs>

   ```python
   from opentelemetry import trace
   from opentelemetry.sdk.trace import TracerProvider
   from opentelemetry.sdk.trace.export import BatchSpanProcessor
   from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

   provider = TracerProvider()
   provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
   trace.set_tracer_provider(provider)
   ```
</Steps>

SideSeat auto-detects framework spans and normalizes them into the workbench timeline.
