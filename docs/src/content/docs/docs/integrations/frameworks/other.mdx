Every framework on this page has a Python SDK integration. Install the extra named in the `pip install`
line, pass the integration name to `sideseat.init`, and wrap each conversation in `sideseat.session`.
Start a local server with `npx sideseat`. Examples that run on Amazon Bedrock need AWS credentials and a
region.

Without the SDK, each section names the instrumentation to install on an OTLP-exporting tracer
provider; the [generic setup](#generic-opentelemetry) at the end shows that provider.

## LangChain

```bash
pip install langchain-aws "sideseat[langchain]"
```

```python
import sideseat
from langchain_aws import ChatBedrockConverse

sideseat.init(integrations=["langchain"])

llm = ChatBedrockConverse(model="global.anthropic.claude-sonnet-5-5")

with sideseat.session("conversation-42", user_id="user-7"):
    print(llm.invoke("Plan a weekend in Lisbon.").text)
```

Without the SDK: `openinference-instrumentation-langchain`, then
`LangChainInstrumentor().instrument(tracer_provider=provider)`. For graphs, see
[LangGraph](/docs/integrations/frameworks/langgraph/).

## Pydantic AI

```bash
pip install "pydantic-ai-slim[bedrock]" "sideseat[pydantic-ai]"
```

```python
import sideseat
from pydantic_ai import Agent

sideseat.init(integrations=["pydantic-ai"])

agent = Agent("bedrock:global.anthropic.claude-sonnet-5-5", instructions="Answer briefly.")

with sideseat.session("conversation-42", user_id="user-7"):
    print(agent.run_sync("Plan a weekend in Lisbon.").output)
```

SideSeat instruments Pydantic AI through Logfire, configured to send nothing to Logfire. Without the
SDK, Pydantic AI's own instrumentation works on any global tracer provider: call
`Agent.instrument_all()` after installing it. The message history Pydantic AI records on each run is
expanded into individual turns, so it does not appear as an extra message.

## LlamaIndex

```bash
pip install llama-index-core llama-index-llms-bedrock-converse "sideseat[llama-index]"
```

```python
import asyncio

import sideseat
from llama_index.core.agent.workflow import FunctionAgent
from llama_index.llms.bedrock_converse import BedrockConverse

sideseat.init(integrations=["llama-index"])


def get_weather(city: str) -> str:
    """Get the weather for a city."""
    return f"Sunny in {city}, 22°C"


agent = FunctionAgent(
    llm=BedrockConverse(model="global.anthropic.claude-sonnet-5-5"),
    tools=[get_weather],
    system_prompt="Answer travel questions.",
)


async def main() -> None:
    with sideseat.session("conversation-42", user_id="user-7"):
        print(await agent.run(user_msg="What's the weather in Lisbon?"))


asyncio.run(main())
```

Without the SDK: `openinference-instrumentation-llama-index`, then
`LlamaIndexInstrumentor().instrument(tracer_provider=provider)`. Workflow and request-preparation spans
stay available as raw spans; their serialized internal state is not shown as conversation messages.

## Semantic Kernel

```bash
pip install "semantic-kernel[aws]" sideseat
```

```python
import asyncio

import sideseat
from semantic_kernel.agents import ChatCompletionAgent
from semantic_kernel.connectors.ai.bedrock import BedrockChatCompletion

sideseat.init(integrations=["semantic-kernel"])

agent = ChatCompletionAgent(
    service=BedrockChatCompletion(model_id="global.anthropic.claude-sonnet-5-5"),
    name="assistant",
    instructions="Answer briefly.",
)


async def main() -> None:
    with sideseat.session("conversation-42", user_id="user-7"):
        print(await agent.get_response(messages="Plan a weekend in Lisbon."))


asyncio.run(main())
```

The integration switches on Semantic Kernel's GenAI diagnostics, content included, and exports the
log records they write: Semantic Kernel records every prompt and completion as a Python log record,
not as a span attribute, so a trace without its logs holds no conversation. Without the SDK, set
`SEMANTICKERNEL_EXPERIMENTAL_GENAI_ENABLE_OTEL_DIAGNOSTICS=true` and
`SEMANTICKERNEL_EXPERIMENTAL_GENAI_ENABLE_OTEL_DIAGNOSTICS_SENSITIVE=true` before Semantic Kernel is
imported, export logs to SideSeat's `/otel/default/v1/logs` endpoint beside the traces, and attach an
OpenTelemetry `LoggingHandler` at `INFO` to the `semantic_kernel` logger. For .NET, use the
`semantic-kernel` integration of the [.NET SDK](/docs/sdks/dotnet/).

import sideseat

## smolagents

```bash
pip install "smolagents[litellm]" "sideseat[smolagents]"
```

```python
import sideseat
from smolagents import LiteLLMModel, ToolCallingAgent

sideseat.init(integrations=["smolagents"])

model = LiteLLMModel(model_id="bedrock/global.anthropic.claude-sonnet-5-5", tool_choice="auto")
agent = ToolCallingAgent(tools=[], model=model)

with sideseat.session("conversation-42", user_id="user-7"):
    print(agent.run("Plan a weekend in Lisbon."))
```

`tool_choice="auto"` lets the model answer without a tool call; smolagents otherwise forces one.
Without the SDK: `openinference-instrumentation-smolagents`, then
`SmolagentsInstrumentor().instrument(tracer_provider=provider)`. smolagents' internal `Calling tools`
and `Observation` renderings are not shown as user messages.

## AG2

```bash
pip install "ag2[bedrock]" "sideseat[ag2]"
```

```python
import asyncio

import sideseat
from ag2 import Agent
from ag2.config import BedrockConfig

sideseat.init(integrations=["ag2"])

assistant = Agent(
    "assistant",
    "Answer briefly.",
    config=BedrockConfig(model="global.anthropic.claude-sonnet-5-5", region_name="us-east-1"),
)


async def main() -> None:
    with sideseat.session("conversation-42", user_id="user-7"):
        reply = await assistant.ask("Plan a weekend in Lisbon.")
        print(await reply.content())


asyncio.run(main())
```

Call `init` before constructing agents: the integration adds AG2's `TelemetryMiddleware` to every agent
created afterwards, and keeps one you passed yourself instead of adding a second. Without the SDK, pass
`middleware=[TelemetryMiddleware(tracer_provider=provider, agent_name="assistant")]` from
`ag2.middleware.builtin` to each agent.

## AgentScope

```bash
pip install "sideseat[agentscope]"
```

```python
import asyncio
import os

import sideseat
from agentscope.agent import Agent
from agentscope.credential import AnthropicCredential
from agentscope.message import UserMsg
from agentscope.model import AnthropicChatModel

sideseat.init(integrations=["agentscope"])


async def main() -> None:
    agent = Agent(
        name="assistant",
        system_prompt="Answer briefly.",
        model=AnthropicChatModel(
            credential=AnthropicCredential(api_key=os.environ["ANTHROPIC_API_KEY"]),
            model="claude-sonnet-5-5",
        ),
    )
    with sideseat.session("conversation-42", user_id="user-7"):
        reply = await agent.reply(UserMsg("user", "Plan a weekend in Lisbon."))
    print(reply.get_text_content())


asyncio.run(main())
```

Call `init` before constructing agents: the integration adds AgentScope's `TracingMiddleware` to every
agent created afterwards. Without the SDK, pass `middlewares=[TracingMiddleware()]` from
`agentscope.middleware` to each agent.

## Haystack

```bash
pip install haystack-ai amazon-bedrock-haystack "sideseat[haystack]"
```

```python
import sideseat
from haystack.components.agents import Agent
from haystack.dataclasses import ChatMessage
from haystack_integrations.components.generators.amazon_bedrock import AmazonBedrockChatGenerator

sideseat.init(integrations=["haystack"])

agent = Agent(
    chat_generator=AmazonBedrockChatGenerator(model="global.anthropic.claude-sonnet-5-5"),
    system_prompt="Answer briefly.",
)

with sideseat.session("conversation-42", user_id="user-7"):
    result = agent.run(messages=[ChatMessage.from_user("Plan a weekend in Lisbon.")])
    print(result["last_message"].text)
```

The integration connects Haystack's tracing API to SideSeat's provider and turns on content tracing.
Without the SDK, install `opentelemetry-haystack`, set
`haystack.tracing.tracer.is_content_tracing_enabled = True`, and call
`haystack.tracing.enable_tracing(OpenTelemetryTracer(provider.get_tracer("haystack")))` with
`OpenTelemetryTracer` from `haystack_integrations.tracing.opentelemetry`.

## Browser Use

```bash
pip install browser-use "sideseat[browser-use]"
```

```python
import asyncio

import sideseat
from browser_use import Agent, ChatAnthropic

sideseat.init(integrations=["browser-use"])


async def main() -> None:
    llm = ChatAnthropic(model="claude-sonnet-5-5", thinking={"type": "adaptive"})
    agent = Agent(task="Find the SideSeat documentation", llm=llm)
    with sideseat.trace("find-docs", session_id="conversation-42", user_id="user-7"):
        history = await agent.run()
    print(history.final_result())


asyncio.run(main())
```

Browser Use's spans come from Laminar, which the `browser-use` extra installs. Laminar owns the tracer
provider, and SideSeat configures it to export to your project and nowhere else:

- Call `sideseat.init` before anything calls `Laminar.initialize`.
- Unset `LMNR_PROJECT_API_KEY` and `LMNR_BASE_URL`; `init` refuses to run with either set, because they
  would send the telemetry to Laminar.
- Model calls are recorded by Laminar's instrumentation of the client library the chat model uses:
  OpenAI, Anthropic, Google Gen AI, Groq, Mistral, Ollama, or LiteLLM. `ChatAWSBedrock` calls
  boto3, which Laminar records only when `opentelemetry-instrumentation-bedrock` is installed.

Each agent step is one model call whose reply is a single `AgentOutput` tool call listing the
browser actions to take. Browser Use then runs every action, built-in or custom, under a tool span
of its own, and SideSeat shows each one as a call and its result; the `done` action's result is the
agent's answer. `AgentOutput` itself has no result, because the actions it lists are the executions.

Without the SDK, set `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to
`http://localhost:5388/otel/default/v1/traces` and `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf`,
then call `Laminar.initialize(force_http=True)` without a project key, and open conversations with
`Laminar.start_as_current_span(name, session_id=..., user_id=...)`. Laminar names the service after
the running program rather than `OTEL_SERVICE_NAME`.

Current Claude models on Bedrock accept only automatic tool choice. `ChatAnthropicBedrock` forces the
`AgentOutput` tool and is rejected; `ChatAnthropic` with adaptive thinking chooses it automatically,
and can be given an `AsyncAnthropicBedrock` client by overriding `get_client`.

## Langflow

Langflow emits OpenTelemetry itself. Run its flows in a process where `sideseat.init(integrations=["langflow"])`
has installed the provider, or point Langflow's own exporter at SideSeat:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
```

Flow spans carry `langflow.flow_id`, `langflow.flow_name`, and `langflow.session_id`.

## Logfire

```bash
pip install "sideseat[logfire]"
```

```python
import logfire
import sideseat

sideseat.init(integrations=["logfire"])

with sideseat.session("conversation-42", user_id="user-7"):
    with logfire.span("plan trip to {city}", city="Lisbon"):
        ...
```

Name `logfire` explicitly: several provider extras install Logfire, so its presence is not taken as a
sign that the application uses it. SideSeat calls `logfire.configure` itself, with nothing sent to
Logfire; do not call it again. Logfire GenAI spans (`events`, `prompt`, `all_messages_events`,
`request_data`, `response_data`) are read as conversations.

## TraceLoop / OpenLLMetry

```bash
pip install openai "sideseat[traceloop]"
```

```python
from openai import OpenAI

import sideseat
from traceloop.sdk.decorators import workflow

sideseat.init(integrations=["traceloop"])
client = OpenAI()


@workflow(name="answer")
def answer(question: str) -> str:
    response = client.chat.completions.create(
        model="gpt-6.1-sol",
        messages=[{"role": "user", "content": question}],
    )
    return response.choices[0].message.content or ""


with sideseat.session("conversation-42", user_id="user-7"):
    print(answer("What is the speed of light?"))
```

Call `init` before the first decorated function runs. TraceLoop enriches spans on SideSeat's provider but
exports nothing itself, `requests` and `urllib3` are not instrumented so OTLP exports cannot trace
themselves, and images stay inline instead of going to TraceLoop's uploader. Decorator inputs and
outputs (`traceloop.entity.input`, `traceloop.entity.output`) are kept as raw span attributes; the
conversation comes from the provider instrumentation's `gen_ai.input.messages` and
`gen_ai.output.messages`.

## Langfuse

```bash
pip install openai "sideseat[langfuse]"
```

```python
import sideseat
from langfuse import observe
from langfuse.openai import OpenAI

sideseat.init(integrations=["langfuse"])
client = OpenAI()


@observe(name="answer", as_type="agent")
def answer(question: str) -> str:
    response = client.chat.completions.create(
        model="gpt-6.1-sol",
        messages=[{"role": "user", "content": question}],
    )
    return response.choices[0].message.content or ""


with sideseat.session("conversation-42", user_id="user-7"):
    print(answer("What is the speed of light?"))
```

Langfuse 4 records its observations as OpenTelemetry spans. The integration gives Langfuse SideSeat's
tracer provider and an exporter that sends nothing to Langfuse's cloud, and turns media upload off so
images and documents stay inline. SideSeat reads each generation's recorded request and response - OpenAI
chat messages, or Responses API items including function calls and their outputs - and classifies tool,
agent, chain, retriever, embedding, evaluator and guardrail observations from Langfuse's own type. The
inputs and outputs of other observations describe your functions rather than the conversation, so they
stay span attributes.

## OpenInference

For spans you write by hand with OpenInference's conventions, wrap SideSeat's tracer in `OITracer`:

```bash
pip install sideseat openinference-instrumentation
```

```python
import sideseat
from openinference.instrumentation import OITracer, TraceConfig

client = sideseat.init(integrations=["openinference"])
tracer = OITracer(client.get_tracer("openinference.instrumentation.generic"), TraceConfig())
```

Create spans with OpenInference's `get_llm_attributes`, `get_tool_attributes`,
`get_retriever_attributes`, and `get_reranker_attributes` helpers. Keep the
`openinference.instrumentation.generic` scope name so generic tool spans are not confused with a
framework instrumentor's.

## Recognised without a setup guide

The server classifies these when their spans arrive through the generic setup below:

| Framework | Recognised by |
| --- | --- |
| Azure AI Foundry | Azure AI attributes, after the more specific Azure OpenAI rule |
| MLflow | MLflow tracing attributes |
| LiveKit | LiveKit Agents attributes |

These are classifier-only. The support matrix in `server/tests/fixtures/messages/README.md` is the exact
boundary of what is verified.

## Generic OpenTelemetry

Any producer that exports OTLP over HTTP works:

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install opentelemetry-sdk opentelemetry-exporter-otlp
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add opentelemetry-sdk opentelemetry-exporter-otlp
    ```
  </TabItem>
</Tabs>

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
```

```python
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(provider)
```

To group traces into a session, give a span in each trace `session.id` and `user.id` attributes.
