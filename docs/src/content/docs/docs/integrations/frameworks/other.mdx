SideSeat works with any framework that emits OpenTelemetry traces. This page covers frameworks without dedicated integration pages.

## LangChain

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install langchain langchain-openai "sideseat[langchain]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add langchain langchain-openai "sideseat[langchain]"
    ```
  </TabItem>
</Tabs>

```python
from sideseat import SideSeat, Frameworks
from langchain_openai import ChatOpenAI

SideSeat(framework=Frameworks.LangChain)

llm = ChatOpenAI(model="gpt-5-mini")
response = llm.invoke("Hello!")
print(response.content)
```

<Aside type="tip">
For stateful agent workflows, use [LangGraph](/docs/integrations/frameworks/langgraph/) instead.
</Aside>

The compatibility corpus exercises LangChain 1.4.3, LangChain Core 1.6.6,
LangChain OpenAI 1.6.7, and OpenInference's LangChain instrumentor 0.1.76 on
OpenTelemetry Python 1.45.0. Native OpenTelemetry and SideSeat SDK captures must
produce identical span projections, two trace conversations, their shared session,
and the project feed. The scenario includes multi-turn history, streaming, and a
complete tool-call roundtrip.

## PydanticAI

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install pydantic-ai "sideseat[pydantic-ai]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add pydantic-ai "sideseat[pydantic-ai]"
    ```
  </TabItem>
</Tabs>

```python
import sideseat
from pydantic_ai import Agent

sideseat.init(integrations=["pydantic-ai"])

agent = Agent("bedrock:global.anthropic.claude-sonnet-5-5")
result = agent.run_sync("What is the capital of France?")
print(result.output)
```

SideSeat instruments Pydantic AI through Logfire, configured to send nothing to Logfire itself.
Without the SDK, Pydantic AI's own OpenTelemetry instrumentation works on any OTLP pipeline:

```python
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from pydantic_ai import Agent

provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(OTLPSpanExporter(endpoint="http://localhost:5388/otel/default/v1/traces"))
)
trace.set_tracer_provider(provider)
Agent.instrument_all()
```

The compatibility corpus exercises Pydantic AI 2.50.0 with and without the SideSeat SDK,
including multi-turn history and tool use. `pydantic_ai.all_messages` is expanded into its
individual turns at read time, so the history snapshot does not appear as an extra context
message beside the model-call spans.

## LlamaIndex

LlamaIndex uses its own instrumentation dispatcher rather than emitting OpenTelemetry directly.
SideSeat's `llama-index` extra installs the OpenInference bridge and binds it to the same tracer
provider and exporter as the rest of the application:

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install llama-index "sideseat[llama-index]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add llama-index "sideseat[llama-index]"
    ```
  </TabItem>
</Tabs>

```python
from sideseat import SideSeat, Frameworks
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

SideSeat(framework=Frameworks.LlamaIndex)

documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()

response = query_engine.query("What is this about?")
print(response)
```

The compatibility corpus exercises LlamaIndex Core 0.14.25, LlamaIndex OpenAI 0.8.2,
OpenInference's LlamaIndex instrumentor 4.5.3, and OpenTelemetry Python 1.45.0 on Python 3.13.
The OpenAI adapter currently requires `openai <3`, so the capture uses OpenAI 2.54.0, the newest
compatible release resolved by the lockfile.

Native OpenTelemetry and SideSeat SDK captures must produce identical span projections, two
trace conversations, their shared session, and the project feed. The scenario covers retained
history, a streamed second answer, and one automatic weather-tool roundtrip. LlamaIndex workflow
and request-preparation spans remain available as raw telemetry, but their serialized internal
state is not presented as conversation messages.

## Agno

```bash
pip install "agno[anthropic,aws-bedrock]" "sideseat[agno]"
```

```python
import sideseat
from agno.agent import Agent
from agno.models.aws import Claude

sideseat.init(integrations=["agno"])

agent = Agent(model=Claude(id="global.anthropic.claude-sonnet-5-5"))
agent.print_response("Hello!")
```

Without the SDK, install `openinference-instrumentation-agno` and call
`AgnoInstrumentor().instrument(tracer_provider=provider)` on an OTLP-exporting tracer provider.

Agno is instrumented through OpenInference. Its spans carry `agno.*` attributes alongside
`openinference.*`, and SideSeat's detection prefers the specific `agno.` prefix so runs are
labelled Agno rather than the generic OpenInference.

The tracked compatibility boundary is Agno 3.0.11 with OpenAI 3.22.1 and the OpenInference
Agno instrumentor 1.0.12 on Python 3.13. It is exercised both natively and through SideSeat
with persisted history, streaming, automatic tool execution, two traces, and one shared session.

## Smolagents

```bash
pip install smolagents "sideseat[smolagents]"
```

```python
from sideseat import SideSeat, Frameworks
from smolagents import OpenAIModel, ToolCallingAgent

SideSeat(framework=Frameworks.Smolagents)

model = OpenAIModel(model_id="gpt-5-mini")
agent = ToolCallingAgent(tools=[], model=model)
agent.run("What is 2+2?")
```

Smolagents uses OpenInference telemetry. Only the agent run span carries `smolagents.*`;
the step, model, and tool spans are identified by the exact
`openinference.instrumentation.smolagents` scope.

The tracked compatibility boundary is Smolagents 1.26.0 with OpenAI 3.22.1, the OpenInference
Smolagents instrumentor 0.1.41, and OpenTelemetry Python 1.45.0 on Python 3.13. Native
OpenTelemetry and SideSeat captures must produce identical span projections, two trace
conversations, their shared session, and the project feed. The scenario retains history across
runs, streams the second answer, executes a custom weather tool, and verifies every
`final_answer` call/result pair without exposing Smolagents' internal `Calling tools` and
`Observation` renderings as user messages.

## AG2

```bash
pip install "ag2[openai]>=1.1.1,<2" "sideseat[ag2]"
```

```python
import asyncio

from ag2 import Agent
from ag2.config import OpenAIConfig
from sideseat import SideSeat, Frameworks

SideSeat(framework=Frameworks.AG2)

assistant = Agent(
    "assistant",
    "Answer briefly.",
    config=OpenAIConfig(model="gpt-5-mini"),
)

async def main():
    reply = await assistant.ask("Hello!")
    print(await reply.content())

asyncio.run(main())
```

Initialize SideSeat before constructing the agent. SideSeat injects AG2 1.x's native
`TelemetryMiddleware` with content capture and the SideSeat tracer provider; an explicit
`TelemetryMiddleware` is preserved rather than duplicated.

The tracked compatibility boundary is AG2 1.1.1 with OpenAI 3.22.1 and OpenTelemetry Python
1.45.0. Native OpenTelemetry and SideSeat captures have identical span projections, two trace
conversations, their shared session, and the project feed. The scenario covers retained history,
streaming, automatic tool execution, and the complete tool call/result/final-answer sequence.

## AgentScope

```bash
pip install "sideseat[agentscope]"
```

```python
import asyncio
import os

from agentscope.agent import Agent
from agentscope.credential import OpenAICredential
from agentscope.message import UserMsg
from agentscope.model import OpenAIChatModel
from sideseat import SideSeat, Frameworks

SideSeat(framework=Frameworks.AgentScope)

async def main():
    model = OpenAIChatModel(
        credential=OpenAICredential(api_key=os.environ["OPENAI_API_KEY"]),
        model="gpt-5-mini",
    )
    agent = Agent(
        name="assistant",
        system_prompt="Answer briefly.",
        model=model,
    )
    reply = await agent.reply(UserMsg("user", "Hello!"))
    print(reply.get_text_content())

asyncio.run(main())
```

Initialize SideSeat before constructing an `Agent`. SideSeat injects AgentScope 2.x's built-in
`TracingMiddleware` into subsequently created agents and preserves an explicit middleware instead
of adding a duplicate.

Without the SDK, install AgentScope and an OTLP exporter, configure the global tracer provider, and
pass the middleware yourself:

```python
from agentscope.middleware import TracingMiddleware

agent = Agent(
    name="assistant",
    system_prompt="Answer briefly.",
    model=model,
    middlewares=[TracingMiddleware()],
)
```

The tracked compatibility boundary is AgentScope 2.0.9 with OpenAI 3.22.1 and OpenTelemetry
Python 1.45.0. Native and SideSeat captures have identical span projections, two ordered trace
conversations, one shared session, and the project feed. The scenario covers retained history,
streaming, automatic tool execution, and a complete call/result/final-answer sequence.

## Langflow

```bash
pip install langflow sideseat
```

Langflow emits OpenTelemetry itself. Either run it in a process where SideSeat has
installed the provider, or point Langflow's own OTLP exporter at SideSeat:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
```

Flow spans carry `langflow.flow_id`, `langflow.flow_name` and `langflow.session_id`.

## Haystack

```bash
pip install haystack-ai "sideseat[haystack]"
```

```python
from sideseat import SideSeat, Frameworks
from haystack import Pipeline
from haystack.components.generators.chat import OpenAIChatGenerator
from haystack.dataclasses import ChatMessage

SideSeat(framework=Frameworks.Haystack)

pipeline = Pipeline()
pipeline.add_component("llm", OpenAIChatGenerator(model="gpt-5-mini"))
result = pipeline.run({"llm": {"messages": [ChatMessage.from_user("Hello")]}})
print(result["llm"]["replies"][0].text)
```

Component spans carry `haystack.component.name` and `haystack.component.type`, which
SideSeat uses to label the run Haystack rather than generic OpenInference.

## Logfire

```bash
pip install "sideseat[logfire]"
```

```python
import logfire
from sideseat import Frameworks, SideSeat

sideseat = SideSeat(framework=Frameworks.Logfire)

with sideseat.trace("answer", session_id="conversation-42"):
    with logfire.span(
        "model call",
        events=[
            {
                "event.name": "gen_ai.user.message",
                "content": "What is the speed of light?",
            }
        ],
        response_data={
            "message": {
                "role": "assistant",
                "content": "299,792,458 metres per second in vacuum.",
            }
        },
        **{"gen_ai.operation.name": "chat"},
    ):
        pass

sideseat.shutdown()
```

Select `Frameworks.Logfire` explicitly. Logfire is a transitive dependency of several provider
extras, so package presence alone is intentionally not treated as evidence that the application
uses generic Logfire spans. SideSeat configures Logfire and owns the OTLP export pipeline; do not
call `logfire.configure()` a second time afterward.

The tracked Logfire 6.0.0b7 native/SideSeat pair covers `events`, `prompt`,
`all_messages_events`, `request_data`, `response_data`, repeated history, a streaming-shaped
response, request-side tool definitions, and a complete call/result/final-answer sequence. Both
paths produce the same six spans, two traces, one shared session, span projections, and project
feed.

## OpenInference

OpenInference is a semantic convention and instrumentation toolkit rather than a framework that
SideSeat auto-patches. Install its base instrumentation package and wrap SideSeat's tracer with the
official `OITracer`:

```bash
pip install sideseat openinference-instrumentation
```

```python
from openinference.instrumentation import OITracer, TraceConfig
from sideseat import SideSeat

sideseat = SideSeat(
    auto_instrument=False,
    service_name="my-openinference-app",
)
tracer = OITracer(
    sideseat.tracer_provider.get_tracer("openinference.instrumentation.generic"),
    TraceConfig(),
)
```

Use OpenInference's `get_llm_attributes`, `get_tool_attributes`, `get_retriever_attributes`,
and `get_reranker_attributes` helpers when creating spans. Keep the
`openinference.instrumentation.generic` scope name so generic TOOL spans are not confused with
framework instrumentors that own their own result carriers. There is no `Frameworks.OpenInference`:
the emitted `openinference.*` attributes identify the dialect directly.

The tracked native/SideSeat pair uses OpenInference instrumentation 0.1.67 and semantic
conventions 0.1.40 on OpenTelemetry Python 1.45.0. It verifies retained multi-turn context,
tool definitions, a complete tool roundtrip with call-id correlation, retrieval and reranking,
three ordered traces, one shared session, and the project feed.

## TraceLoop / OpenLLMetry

Use SideSeat's TraceLoop extra rather than installing `traceloop-sdk` alone. It supplies the
runtime HTTP dependencies missing from TraceLoop 0.62.4's package metadata and keeps `httpx`
below 1.0, whose prereleases no longer expose the API that this TraceLoop release imports:

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install openai "sideseat[traceloop]"
    ```
  </TabItem>
  <TabItem label="uv">
    ```bash
    uv add openai "sideseat[traceloop]"
    ```
  </TabItem>
</Tabs>

Initialize SideSeat before the first decorated function is called:

```python
from openai import OpenAI
from sideseat import Frameworks, SideSeat
from traceloop.sdk.decorators import workflow

sideseat = SideSeat(framework=Frameworks.TraceLoop)
client = OpenAI()


@workflow(name="answer")
def answer(question: str) -> str:
    response = client.chat.completions.create(
        model="gpt-5-mini",
        messages=[{"role": "user", "content": question}],
    )
    return response.choices[0].message.content or ""


try:
    print(answer("What is the speed of light?"))
finally:
    sideseat.shutdown()
```

SideSeat lets TraceLoop enrich the global OpenTelemetry provider but does not install a second
exporter. It also excludes `requests` and `urllib3` instrumentation so exporting an OTLP batch
cannot recursively trace itself, applies SideSeat's `capture_content` policy, and keeps inline
image data in telemetry instead of invoking TraceLoop's hosted image uploader.

TraceLoop decorators serialize arbitrary function arguments and return values under
`traceloop.entity.input` and `traceloop.entity.output`. SideSeat preserves those raw attributes
for span inspection but does not reinterpret them as conversation turns. The provider
instrumentor's `gen_ai.input.messages` and `gen_ai.output.messages` attributes are the
authoritative chat carriers.

The tracked native/SideSeat pair uses TraceLoop SDK 0.62.4, OpenAI 3.22.1, OpenTelemetry Python
1.45.0, and CPython 3.12.8. It verifies retained history, a streamed second response,
workflow/task/agent/tool decorators, one complete tool-call roundtrip, two traces, ten spans,
one shared session, and identical span, trace, session, and project-feed projections.

## Recognised without a setup guide

The server classifies these, but nothing here tells you how to wire them up — each already emits
OpenTelemetry on its own, so the generic setup below is the whole instruction and the spans are
attributed once they arrive:

| Framework | Recognised by |
| --- | --- |
| Semantic Kernel | current Python instrumentation scopes and `semantic_kernel.*` attributes |
| Azure AI Foundry | Azure AI attributes, after the more specific Azure OpenAI rule |
| MLflow | MLflow tracing attributes |
| LiveKit | LiveKit Agents attributes |

Semantic Kernel is exercised by paired native/SideSeat captures. The other rows are
classifier-only. The support matrix in
`server/tests/fixtures/messages/README.md` is the exact boundary of what is verified.

## Generic OpenTelemetry

For frameworks not listed above, send traces directly via the OpenTelemetry SDK:

<Steps>
1. **Start SideSeat**

   ```bash
   npx sideseat
   ```

2. **Set the endpoint**

   ```bash
   export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5388/otel/default
   ```

3. **Install and configure**

   <Tabs>
     <TabItem label="pip">
       ```bash
       pip install opentelemetry-sdk opentelemetry-exporter-otlp
       ```
     </TabItem>
     <TabItem label="uv">
       ```bash
       uv add opentelemetry-sdk opentelemetry-exporter-otlp
       ```
     </TabItem>
   </Tabs>

   ```python
   from opentelemetry import trace
   from opentelemetry.sdk.trace import TracerProvider
   from opentelemetry.sdk.trace.export import BatchSpanProcessor
   from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

   provider = TracerProvider()
   provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
   trace.set_tracer_provider(provider)
   ```
</Steps>

SideSeat auto-detects framework spans and normalizes them into the workbench timeline.
