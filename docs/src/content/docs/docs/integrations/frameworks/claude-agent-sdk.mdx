The [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk) is Claude Code packaged as a library:
built-in file and shell tools, the agent loop, subagents, hooks, and permissions.

The SDK emits no telemetry in your process. It spawns the Claude Code CLI as a child process, and the
CLI exports OpenTelemetry itself, configured through environment variables. The `claude-agent-sdk`
integration sets those variables for every CLI the SDK spawns, and the SDK passes the active span to the
CLI as `TRACEPARENT`, so the CLI's spans join your trace.

## Install

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```bash
    pip install claude-agent-sdk sideseat
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```bash
    npm install @anthropic-ai/claude-agent-sdk @sideseat/sdk
    ```
  </TabItem>
</Tabs>

Start a local server with `npx sideseat` and set `ANTHROPIC_API_KEY`, or configure
[Bedrock](#amazon-bedrock).

## Quick start

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    import asyncio

    import sideseat
    from claude_agent_sdk import ClaudeAgentOptions, query

    sideseat.init(integrations=["claude-agent-sdk"])


    async def main() -> None:
        options = ClaudeAgentOptions(model="claude-sonnet-5-5", allowed_tools=["Read", "Glob"])
        with sideseat.trace("summarize-repo", session_id="conversation-42", user_id="user-7"):
            async for message in query(prompt="Summarize the README in this directory.", options=options):
                print(message)


    asyncio.run(main())
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```ts
    import * as sideseat from "@sideseat/sdk";
    import { query } from "@anthropic-ai/claude-agent-sdk";

    await sideseat.init({ integrations: ["claude-agent-sdk"] });

    await sideseat.trace(
      "summarize-repo",
      { sessionId: "conversation-42", userId: "user-7" },
      async () => {
        for await (const message of query({
          prompt: "Summarize the README in this directory.",
          options: { model: "claude-sonnet-5-5", allowedTools: ["Read", "Glob"] },
        })) {
          console.log(message);
        }
      },
    );
    ```
  </TabItem>
</Tabs>

Start the run inside `trace()` rather than only `session()`: the CLI is another process, so it does not
see the session scope, but its spans join the trace whose root carries the session.

<Aside type="caution" title="TypeScript: spread process.env into options.env">
The TypeScript integration sets the variables on `process.env`, which the CLI inherits. `options.env`
replaces the inherited environment, so if you pass it, write `env: { ...process.env, ...yours }`. In
Python, `ClaudeAgentOptions.env` is merged on top of the integration's variables.
</Aside>

## Without the SDK

Export the variables yourself; the CLI inherits them:

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1
export ENABLE_BETA_TRACING_DETAILED=1
export BETA_TRACING_ENDPOINT=http://localhost:5388/otel/default
export OTEL_TRACES_EXPORTER=otlp
export OTEL_METRICS_EXPORTER=none
export OTEL_LOGS_EXPORTER=none
export OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:5388/otel/default/v1/traces
export OTEL_TRACES_EXPORT_INTERVAL=1000
export OTEL_LOG_USER_PROMPTS=1
export OTEL_LOG_TOOL_DETAILS=1
```

| Variable | Why |
| --- | --- |
| `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA` | Span tracing is a beta tier; without it the CLI exports only metrics and logs. |
| `ENABLE_BETA_TRACING_DETAILED`, `BETA_TRACING_ENDPOINT` | The second tier is the only one that puts the conversation on spans. The endpoint is a base URL; a `/v1/traces` path returns 404. |
| `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS` | Prompt text and tool arguments are redacted without them. |
| `OTEL_TRACES_EXPORT_INTERVAL` | Short runs exit before the default five-second batch interval. |

Never set an `OTEL_*_EXPORTER` to `console`: the CLI's stdout is the Agent SDK's message channel.

## What you see in SideSeat

```
claude_code.interaction              one turn of the agent loop
├── claude_code.llm_request          one Claude API call
├── claude_code.tool                 one tool invocation
│   ├── claude_code.tool.blocked_on_user
│   └── claude_code.tool.execution
└── claude_code.hook
```

- System prompt, user turns, tool results, and assistant replies in the Messages tab.
- Token counts and cost on every `llm_request` span.
- A subagent's spans nested under the `claude_code.tool` span that delegated to it, in the same trace.

## Amazon Bedrock

```bash
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1
export ANTHROPIC_MODEL=global.anthropic.claude-sonnet-5-5
export ANTHROPIC_DEFAULT_HAIKU_MODEL=global.anthropic.claude-haiku-4-5-20251001-v1:0
```

Drop the `model` option from the snippets above so `ANTHROPIC_MODEL` applies. WebSearch is not
available on Bedrock.

## Known limits

- Tracing in Claude Code is a beta: span names and attributes can change between releases.
- The CLI's metrics and log events are turned off; the spans carry the same tokens and cost.
- Export failures are written to the CLI's stderr (`CLAUDE_CODE_OTEL_DIAG_STDERR=1`, set by the
  integration). Read them through the Agent SDK's `stderr` callback.
