The SideSeat REST API provides programmatic access to run data (traces), session management, and real-time streaming.

## Base URL

All API endpoints are prefixed with `/api/v1/project/{project_id}/otel`.

```
http://localhost:5388/api/v1/project/default/otel
```

The default project ID is `default`.

## Authentication

When authentication is enabled, include a Bearer token in requests:

```bash
curl -H "Authorization: Bearer your-token" \
  http://localhost:5388/api/v1/project/default/otel/traces
```

See [Authentication](/docs/reference/auth/) for details on obtaining tokens.

## Pagination

List endpoints use page-based pagination.

**Query Parameters:**
- `page` - Page number (default: 1)
- `limit` - Items per page (default: 50)

**Response Fields:**
- `data` - Array of results
- `meta` - Pagination metadata (`page`, `limit`, `total_items`, `total_pages`)

```bash
# First page
curl "http://localhost:5388/api/v1/project/default/otel/traces?page=1&limit=20"

# Next page
curl "http://localhost:5388/api/v1/project/default/otel/traces?page=2&limit=20"
```

## Error Responses

All errors follow a consistent format:

```json
{
  "error": "error_type",
  "code": "ERROR_CODE",
  "message": "Human-readable error message"
}
```

**Common Error Codes:**

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `TRACE_NOT_FOUND` | 404 | Trace does not exist |
| `SPAN_NOT_FOUND` | 404 | Span does not exist |
| `SESSION_NOT_FOUND` | 404 | Session does not exist |
| `STORAGE_ERROR` | 500 | Database error |
| `AUTH_REQUIRED` | 401 | Authentication required |
| `TOKEN_EXPIRED` | 401 | Token has expired |

## SDK Runtime

The SideSeat SDKs register their agents, MCP servers, swarms and graphs with the server, which can then run them:

| Endpoint | Description |
|----------|-------------|
| `GET /api/v1/project/{project_id}/ws` | WebSocket an SDK registers over |
| `GET /api/v1/project/{project_id}/registrations` | The live registrations, by kind |
| `GET /api/v1/project/{project_id}/presence` | Server-sent events as registrations come and go |
| `POST /api/v1/project/{project_id}/agents/{name}/runs` | Run a registered agent, streaming its AG-UI events |

## Credentials

Model-provider credentials belong to an organization; permission rules say which of its projects may use each:

| Endpoint | Description |
|----------|-------------|
| `GET`, `POST /api/v1/organizations/{org_id}/credentials` | List or create credentials |
| `PATCH`, `DELETE /api/v1/organizations/{org_id}/credentials/{id}` | Update or delete a credential |
| `POST /api/v1/organizations/{org_id}/credentials/{id}/test` | Test a credential's connectivity |
| `GET`, `POST /api/v1/organizations/{org_id}/credentials/{id}/permissions` | List or add its permission rules |
| `DELETE /api/v1/organizations/{org_id}/credentials/{id}/permissions/{perm_id}` | Delete a permission rule |

The full, generated reference is the server's OpenAPI document at `/api/openapi.json`, browsable at `/api/docs`.

## Health Check

```
GET /api/v1/health
```

Returns server health status:

```json
{
  "status": "ok",
  "version": "1.0.5"
}
```

It answers `503` with `"status": "failed"` once the embedded analytics database (DuckDB) has failed in a way only
a restart recovers, such as a checkpoint that could not complete. The server then shuts down and exits with a
non-zero status, so a supervisor starts it again; the reason is in the server's log. Nothing whose ingestion was
acknowledged is lost: it is in the database when it reopens, or written again from staging.

## OTLP Ingestion

Traces are ingested via OTLP endpoints:

```
POST /otel/{project_id}/v1/traces
POST /otel/{project_id}/v1/metrics
POST /otel/{project_id}/v1/logs
```

See [OpenTelemetry Reference](/docs/reference/otel/) for ingestion details.
